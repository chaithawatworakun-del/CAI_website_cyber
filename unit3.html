UNIT 03 • โพรโทคอลและการสื่อสาร

การรับส่งข้อมูลบนเครือข่าย

Data Transmission, OSI Model 7 Layers, TCP/IP and IP Addressing

เวลาเรียน: 3 ชั่วโมง วิดีโอบทเรียน OSI 7 Layers & TCP/IP สรุปสาระสำคัญ

จุดประสงค์การเรียนรู้

เมื่อศึกษาหน่วยนี้แล้ว ผู้เรียนจะมีความรู้ความสามารถดังนี้

1. อธิบายหน้าที่ของแต่ละชั้นในแบบจำลอง OSI Model 7 Layers และ TCP/IP Model ได้
2. จำแนกความแตกต่างระหว่างหมายเลข IP Address (Logical Address) และ MAC Address (Physical Address) ได้
3. อธิบายโครงสร้างหมายเลข IPv4 คลาส A, B, C และความจำเป็นในการเปลี่ยนผ่านสู่ IPv6
4. เข้าใจบทบาทหน้าที่ของ Subnet Mask, Default Gateway และ DNS Server ในการเชื่อมต่ออินเทอร์เน็ต

วิดีโอเสริมการเรียนรู้: การสื่อสารข้อมูลและเครือข่ายคอมพิวเตอร์

ทำความเข้าใจภาพรวมกระบวนการรับส่งข้อมูล แบบจำลองเครือข่าย และพื้นฐาน Data Communication

บทเรียนมัลติมีเดีย
หากมีข้อจำกัดด้านเบราว์เซอร์หรือเครื่องขัดข้อง สามารถเปิดดูผ่าน YouTube ได้โดยตรง: เปิดดูบน YouTube

ประเด็นสำคัญในคลิปวิดีโอ:

  • องค์ประกอบและขั้นตอนการส่งผ่านข้อมูลในระบบเครือข่าย
  • หลักการทำงานตามแบบจำลอง OSI และโพรโทคอล TCP/IP
  • การระบุตำแหน่งปลายทางด้วยหมายเลข IP และ Subnet
คำแนะนำสำหรับผู้เรียน

เมื่อดูคลิปจบแล้ว แนะนำให้ศึกษาตารางชั้น OSI 7 Layers และขั้นตอน TCP 3-Way Handshake อย่างละเอียดในหัวข้อด้านล่าง

3.1

แบบจำลองมาตรฐาน OSI 7 Layers และกลไก Encapsulation

OSI Model (Open Systems Interconnection) คือ แบบจำลองอ้างอิงมาตรฐานสากลที่กำหนดโดย ISO แบ่งขั้นตอนการสื่อสารข้อมูลออกเป็น 7 ระดับชั้น (Layers) ช่วยให้อุปกรณ์ต่างผู้ผลิตสามารถทำงานร่วมกันได้อย่างราบรื่น

7
Application Layer ชั้นประยุกต์
ส่วนต่อประสานกับผู้ใช้และซอฟต์แวร์ เช่น เว็บบราวเซอร์ อีเมลไคลเอนต์ (HTTP, HTTPS, DNS, FTP, SMTP, SSH) Data
6
Presentation Layer ชั้นนำเสนอ
แปลงรหัสข้อมูลให้อยู่ในรูปแบบเดียวกัน บีบอัดข้อมูล (Compression) และเข้ารหัสความปลอดภัย (SSL/TLS, JPEG, MP4, ASCII) Data
5
Session Layer ชั้นเซสชัน
สร้าง รักษา ควบคุม และยุติการเชื่อมต่อระหว่างแอปพลิเคชันต้นทางและปลายทาง (RPC, NetBIOS, Sockets) Data
4
Transport Layer ชั้นขนส่งข้อมูล (End-to-End)
ควบคุมการแบ่งส่วนข้อมูล จัดลำดับ ตรวจสอบความถูกต้อง และระบุพอร์ตปลายทาง (TCP, UDP, Port 80, Port 443) Segment
3
Network Layer ชั้นเครือข่ายและการค้นหาเส้นทาง
ค้นหาเส้นทางที่ดีที่สุด (Routing) และระบุที่อยู่ตรรกะ Logical Address (IPv4, IPv6, ICMP, Router) Packet
2
Data Link Layer ชั้นเชื่อมโยงข้อมูลฮาร์ดแวร์
ส่งต่อข้อมูลข้ามโหนดฮาร์ดแวร์ผ่าน MAC Address และตรวจสอบข้อผิดพลาด FCS (Switch, Ethernet 802.3, Wi-Fi 802.11) Frame
1
Physical Layer ชั้นกายภาพ
แปลงข้อมูลเป็นสัญญาณไฟฟ้า แสง หรือคลื่นวิทยุ วิ่งผ่านตัวกลางจริง (สาย UTP, สาย Fiber Optic, Hub, Transceiver) Bits (0, 1)

กระบวนการ Encapsulation vs Decapsulation:

• Encapsulation (ฝั่งผู้ส่ง): ข้อมูลจาก Application ถูกส่งลงมาทีละชั้น โดยแต่ละชั้นจะเพิ่มส่วนหัว (Header) ของตนเอง: Data -> Segment (+TCP Header) -> Packet (+IP Header) -> Frame (+MAC Header & Trailer) -> Bits ออกสู่สายสัญญาณ
• Decapsulation (ฝั่งผู้รับ): เมื่อผู้รับได้รับบิตข้อมูล จะถอดส่วนหัวออกทีละชั้นย้อนกลับขึ้นไปจนถึงข้อมูลดิบที่แอปพลิเคชันต้องการ

3.2

โพรโทคอลชั้นขนส่ง: TCP vs UDP และกลไก 3-Way Handshake

Connection-Oriented

TCP (Transmission Control Protocol)

เน้นความถูกต้อง แม่นยำ ครบถ้วน 100%

ต้องสร้างการเชื่อมต่อก่อนส่งข้อมูลจริง (3-Way Handshake) มีระบบตอบรับ (Acknowledgement) หากแพ็กเกจสูญหายจะส่งซ้ำใหม่ (Retransmission) และจัดเรียงข้อมูลตามลำดับที่ถูกต้อง

การใช้งาน: เปิดเว็บ (HTTP/HTTPS), ส่งไฟล์ (FTP), รับส่งอีเมล (SMTP/IMAP), เข้าจัดการเครื่องระยะไกล (SSH)
Connectionless

UDP (User Datagram Protocol)

เน้นความรวดเร็ว ความหน่วงต่ำพิเศษ (Low Latency)

ส่งข้อมูลทันทีโดยไม่ต้องเชื่อมต่อ ไม่มีการส่งสัญญาณตอบรับ (No ACK) หากข้อมูลหล่นหายจะไม่ส่งซ้ำ เพื่อรักษาความต่อเนื่องของภาพและเสียงในเวลาจริง

การใช้งาน: Live Streaming (YouTube Live, Twitch), โทรศัพท์ผ่านเน็ต (VoIP/Zoom), เกมออนไลน์ (Online Gaming), DNS Lookup

ขั้นตอนการทำงานของ TCP 3-Way Handshake:

Step 1: SYN (Synchronize)

Client ส่งคำขอขอเริ่มการเชื่อมต่อไปยัง Server พร้อมกำหนดหมายเลข Sequence เริ่มต้น

Step 2: SYN-ACK

Server ตอบรับการเชื่อมต่อและส่งสัญญาณยินยอมกลับมาพร้อมกับหมายเลข Sequence ของตนเอง

Step 3: ACK (Acknowledge)

Client ตอบรับการยืนยัน และพร้อมเริ่มต้นส่งข้อมูลจริงอย่างปลอดภัย (Established Connection)

3.3

หมายเลขไอพี (IP Addressing) และการแบ่งคลาส IPv4 / IPv6

โครงสร้าง IPv4 (32-bit Address)

ประกอบด้วย 32 บิต แบ่งออกเป็น 4 ส่วน (Octet ละ 8 บิต) คั่นด้วยจุด เช่น 192.168.1.100 มีจำนวนไอพีทั้งหมดประมาณ 4,294,967,296 หมายเลข

คลาส ช่วงไอพี (IP Range) Default Subnet ขนาดเครือข่าย
Class A 1.0.0.0 – 126.255.255.255 255.0.0.0 (/8) เครือข่ายขนาดใหญ่มาก (16M Hosts)
Class B 128.0.0.0 – 191.255.255.255 255.255.0.0 (/16) เครือข่ายขนาดกลาง (65,534 Hosts)
Class C 192.0.0.0 – 223.255.255.255 255.255.255.0 (/24) เครือข่ายขนาดเล็ก (254 Hosts - นิยมสุด)

ช่วง Private IP Address สำหรับใช้งานภายใน (RFC 1918):

เป็นหมายเลขไอพีสงวนไว้ใช้ภายในองค์กรหรือบ้านฟรี ไม่วิ่งบนอินเทอร์เน็ตสาธารณะ:

  • • Class A Private: 10.0.0.0 – 10.255.255.255 (/8)
  • • Class B Private: 172.16.0.0 – 172.31.255.255 (/12)
  • • Class C Private: 192.168.0.0 – 192.168.255.255 (/16)

IPv6 (128-bit Next Gen)

แก้ปัญหา IPv4 หมดโลก ขนาด 128 บิต เขียนด้วยเลขฐานสิบหก 8 กลุ่ม คั่นด้วยโคลอน เช่น 2001:0db8:85a3::8a2e:0370:7334 รองรับได้ถึง 340 ล้านล้านล้านล้านล้านหมายเลข และมีระบบความปลอดภัย IPSec ฝังมาในตัว

3.4

โพรโทคอลบริการเครือข่ายและหมายเลขพอร์ตมาตรฐาน (Well-Known Ports)

พอร์ต (Port Number) โพรโทคอล (Protocol) Transport หน้าที่และคำอธิบาย
Port 80 HTTP TCP เรียกดูหน้าเว็บไซต์แบบธรรมดา (ไม่เข้ารหัส)
Port 443 HTTPS TCP เรียกดูหน้าเว็บไซต์แบบปลอดภัย เข้ารหัสข้อมูลด้วย SSL/TLS (มาตรฐานปัจจุบัน)
Port 53 DNS UDP / TCP แปลงชื่อโดเมน (เช่น www.google.com) เป็น IP Address
Port 67 / 68 DHCP UDP จ่ายหมายเลข IP และการตั้งค่าเน็ตเวิร์กให้อุปกรณ์ลูกข่ายอัตโนมัติ (DORA Process)
Port 22 SSH TCP รีโมทคอนโทรลเข้าควบคุมเซิร์ฟเวอร์แบบเข้ารหัสความปลอดภัยสูง
Port 20 / 21 FTP TCP โอนย้ายไฟล์ข้อมูลระหว่างไคลเอนต์กับเซิร์ฟเวอร์
3.5

คำสั่ง Command Line พื้นฐานสำหรับการตรวจสอบและแก้ปัญหาเครือข่าย

> ping <target_ip>

ส่งแพ็กเกจ ICMP Echo Request ไปทดสอบว่าเครื่องปลายทางยังเปิดอยู่และตอบสนองหรือไม่ พร้อมวัดความหน่วง (Latency ms)

> tracert <domain>

แกะรอยเส้นทางการเดินทางของแพ็กเกจข้อมูลว่าวิ่งผ่านเราเตอร์ตัวไหนบ้าง (Hop-by-Hop) เพื่อหาจุดที่ระบบล่ม

> ipconfig /all

แสดงค่าคอนฟิก IP Address, Subnet Mask, Default Gateway, DNS Server และ MAC Address ของการ์ดแลนในเครื่อง

> nslookup <domain>

สืบค้นฐานข้อมูล DNS เพื่อดูว่าชื่อเว็บไซต์ดังกล่าวแปลงเป็นหมายเลข IP Address อะไร และใช้ DNS Server ตัวใด

> netstat -ano

แสดงรายการเชื่อมต่อเครือข่ายทั้งหมดในปัจจุบัน ทั้งพอร์ตที่กำลังรอรับข้อมูล (LISTENING) และสถานะการเชื่อมต่อ (ESTABLISHED) พร้อมเลข PID

สรุปประเด็นสำคัญประจำหน่วยที่ 3 (Key Takeaways)

ทบทวนสาระสำคัญด้านการรับส่งข้อมูลและโพรโทคอล

OSI 7 Layers: Physical (Bits) -> Data Link (Frames) -> Network (Packets) -> Transport (Segments) -> Session -> Presentation -> Application
TCP vs UDP: TCP เชื่อถือได้สูงด้วย 3-Way Handshake (SYN-SYN/ACK-ACK) ส่วน UDP รวดเร็ว ความหน่วงต่ำ เหมาะกับ Streaming/Gaming
IPv4 vs IPv6: IPv4 มี 32 บิต (4 Octets) แบ่ง Class A, B, C ส่วน IPv6 มี 128 บิต เพื่อแก้ปัญหาไอพีไม่เพียงพอ
Well-Known Ports: HTTP (80), HTTPS (443 - ปลอดภัย), DNS (53), DHCP (67/68), SSH (22)
Private IP (RFC 1918): ช่วงไอพี 10.x.x.x, 172.16.x.x - 172.31.x.x, 192.168.x.x สงวนไว้ใช้ฟรีในเครือข่ายภายใน
Diagnostic Tools: `ping` เช็คการเชื่อมต่อ, `tracert` ดูเส้นทาง, `ipconfig` ดูไอพีเครื่อง, `nslookup` เช็ค DNS
